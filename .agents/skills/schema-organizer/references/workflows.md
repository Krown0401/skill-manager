# Schema 整理操作指南

## 标准操作流程

### Step 1: 确定影响范围
使用以下方法之一：
1. **关键字搜索**: 搜索受影响的字段名、组件名
2. **文件模式匹配**: 按单据类型、院区筛选
3. **依赖分析**: 查看模板组件的引用情况

### Step 2: 分析当前配置
读取目标 schema 文件，记录：
- [ ] 字段总数和结构
- [ ] 使用的关键组件
- [ ] 特殊的校验规则
- [ ] 联动逻辑配置
- [ ] 与标准配置的差异

### Step 3: 制定修改方案
根据变动类型选择策略：
- **小改动** (字段属性调整): 直接修改目标文件，保持其他配置不变
- **中等改动** (新增/删除字段): 先修改标准配置模板，再同步到各院区
- **大改动** (结构调整): 创建新的配置版本，逐步迁移各院区数据

### Step 4: 执行修改
1. **优先级**: 先修改 `单据配置/` 下的标准配置
2. **兼容性**: 保留必要的向后兼容逻辑
3. **验证**: 修改后立即验证 schema 有效性
4. **文档**: 在 git commit 中说明改动原因

### Step 5: 验证测试
- [ ] Schema JSON 格式有效
- [ ] 字段联动逻辑正常
- [ ] 校验规则生效
- [ ] 默认值正确加载
- [ ] 提交数据格式正确

## 最佳实践

### 1. Schema 版本管理
- 使用 git 标签标记重要版本
- 在 commit message 中注明影响的单据类型
- 重大改动创建迁移文档

### 2. 配置复用
- 通用逻辑放在 `模板组件/`
- 院区特殊配置单独维护
- 定期合并院区间的通用改进

### 3. 变更沟通
- 修改前通知相关院区负责人
- 提供改动影响分析报告
- 预留足够的测试时间

### 4. 质量控制
- 新增字段必须配置 title 和 description
- 复杂联动逻辑需要添加注释
- 定期清理未使用的字段配置

## 常见问题 (FAQ)

### Q1: 如何确定某个字段在哪些单据中使用？
**A:** 使用全局搜索功能，搜索字段的 name 属性：
`grep -r '"name": "yourFieldName"' --include="*.json" .`

### Q2: 院区配置和标准配置不一致怎么办？
**A:** 
1. 先分析差异原因（业务需求 or 历史遗留）
2. 如果是业务需求，保留院区特殊配置
3. 如果是历史问题，制定迁移计划统一配置

### Q3: 修改 schema 后如何快速验证？
**A:**
1. 使用 JSON 验证工具检查格式
2. 在开发环境加载表单预览
3. 测试字段联动和校验功能
